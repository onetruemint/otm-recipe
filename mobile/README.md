# Welcome to your Expo app 👋

This is an [Expo](https://expo.dev) project created with [`create-expo-app`](https://www.npmjs.com/package/create-expo-app).

## Get started

1. Install dependencies

   ```bash
   npm install
   ```

2. Start the app

   ```bash
   npx expo start
   ```

In the output, you'll find options to open the app in a

- [development build](https://docs.expo.dev/develop/development-builds/introduction/)
- [Android emulator](https://docs.expo.dev/workflow/android-studio-emulator/)
- [iOS simulator](https://docs.expo.dev/workflow/ios-simulator/)
- [Expo Go](https://expo.dev/go), a limited sandbox for trying out app development with Expo

You can start developing by editing the files inside the **app** directory. This project uses [file-based routing](https://docs.expo.dev/router/introduction).

## Environment setup

This app talks to Supabase directly (no custom API server). It reads env
vars from `.env` (via `expo-constants`' automatic `EXPO_PUBLIC_*` inlining —
no extra config needed):

- `EXPO_PUBLIC_SUPABASE_URL` — required.
- `EXPO_PUBLIC_SUPABASE_ANON_KEY` — required.
- `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID`, `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` —
  optional for now. Google sign-in shows a "not configured" error until the
  owner sets these (see `.env.example` and `docs/PROGRESS.md`).

To set up a new checkout:

1. Copy the template: `cp .env.example .env` (from `/mobile`). `.env` is
   gitignored — never commit real values.
2. Get values for local development (preferred — requires Docker):
   - From the repo root, run `supabase start` (or `npx supabase start` if
     you don't have the CLI installed globally).
   - Copy the printed `API URL` into `EXPO_PUBLIC_SUPABASE_URL` and the
     printed `anon key` into `EXPO_PUBLIC_SUPABASE_ANON_KEY`.
   - Run `supabase stop` when you're done to free up Docker resources.
3. Alternatively, use the `mint-recipe-prod` production project (Supabase
   dashboard → Project Settings → API) — see `docs/PROGRESS.md` for why this
   is a free-tier project and its current limitations.

After changing `.env`, restart `expo start` — Expo only inlines
`EXPO_PUBLIC_*` vars at process start.

### Regenerating database types

`src/lib/database.types.ts` is generated by the Supabase CLI, not written by
hand. After any migration under `/supabase/migrations` changes, regenerate
it against your local stack and commit the result:

```bash
supabase start   # if not already running
npm run db:types
```

## Get a fresh project

When you're ready, run:

```bash
npm run reset-project
```

This command will move the starter code to the **app-example** directory and create a blank **app** directory where you can start developing.
